# Integration notes (real simulation in the browser)

## Layout and commands
- `crates/sim-wasm`: thin wasm-bindgen shell over `sim_api::Api`. JSON strings in and out; every reply is `{"ok":true,"value":..}` or `{"ok":false,"error":{"code","message"}}`. Content is embedded by `sim-api` (`include_str!`). Class `WasmSim` (`init(seed, paramsJson?)`, `levers`, `actions`, `snapshot`, `preview`, `submit_turn`, `cancel_pending`, `export_state`, `import_state`) plus `install_panic_hook` and `last_panic`.
- Build: `cd web && npm run build:wasm` (cargo release build for `wasm32-unknown-unknown`, then `wasm-bindgen --target web` into `web/src/sim-port/wasm/pkg/`, gitignored). Needs `rustup target add wasm32-unknown-unknown` and `cargo install wasm-bindgen-cli --version 0.2.130 --locked` (must equal the `wasm-bindgen` version in `Cargo.lock`; the script checks and prints the command). `wasm-opt` is used when installed (it was not here).
- Run: `npm run dev` / `npm run build`. Default sim = wasm when `pkg/` exists, else mock with a visible notice and a console warning. Override with `?sim=wasm|mock` or `VITE_SIM`. The top bar badge says "Real simulation" or "Mock data" (from `snapshot.mock`, which only the mock sets).
- Size (release, no wasm-opt): about 1.15 MiB raw, about 295 KiB gzipped.

## Unsafe code and panics
Logic crates keep `forbid(unsafe_code)`. `sim-wasm` uses `unsafe_code = "deny"` instead of the workspace `forbid` because the code generated by wasm-bindgen macros is unsafe; the crate's own code has none. wasm panics abort (no `catch_unwind`), so inputs are validated in `sim-api` (bad commands become `rejected`/`invalid_command`, bad JSON becomes `bad_request`, bad seeds are refused). A panic hook stores the message; `createWasmPort` turns the resulting trap into an error result with `code: "wasm_panic"`.

## Determinism
`libm` is used for every transcendental function in the logic crates (a grep for `.exp()`, `.ln()`, `.powf()`, `.powi()`, trig finds none), `serde_json` has `float_roundtrip`. Golden test: `tests/golden/plan.json` (seed 7, 26 scripted turns, a cancel, an export and import) is replayed natively by `crates/sim-wasm/tests/golden.rs` and in wasm by `web/tests/wasm-golden.test.ts`, comparing an FNV-1a 64 hash of every whole JSON reply (plus headline floats) with `tests/golden/seed7.json`. Result: native and wasm are bit-identical (all 26 turn replies, init, levers, actions, export, import, final snapshot). Refresh the golden file with `UPDATE_GOLDEN=1 cargo test -p sim-wasm --test golden` (only after an intended simulation change).

## Playability check (wasm, Playwright, port 5178)
Costs shown equal costs charged: carbon price 0 to 50 = 12.527 PC and one renewable plant = 2 PC, $2,000,000 in the plan tray; `accepted[].pcCost` and `moneyCost` were identical and PC went 60 to 51.12 (60 - 14.53 + 5.6 regen). Rotate, save (download) and load (turn 2 with 2 pending restored) work. End turn through the store: mean 1.2 ms, max 2.4 ms per turn (sim, JSON parse and store); the wasm call alone 0.5 ms. A no-action style game ends on turn 37 (`legitimacy_zero`); the results modal offers "See the ending", the end screen shows "You lost - The town collapsed", with five sparklines and "New game", which works. Forest and commons show as percentages. Observed oddities: events carry unrounded people counts (fixed); "unemployment 0.0%" at turn 7 and 15.7% at turn 12 swing a lot (model); building counts follow capacity (5 fossil, 1 renewable after the build); `flows.purchases` stays empty.
